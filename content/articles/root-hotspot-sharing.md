手机里的应用通过 v2rayNG 正常访问，不代表连到手机热点的电脑也经过同一路径。热点设备的转发流量与手机本机应用流量不同，需要分别验证。

## 官方功能的权限条件

2026-10-04 官方稳定版 2.2.6 发布说明增加了两项需要 root 的功能：无需 VPN 服务的系统级运行模式，以及热点网络共享。普通 Android VPN 授权与 root 授权不是同一种权限。

本文只帮助已具备相应权限的用户理解功能边界，不提供手机 root 教程。没有 root 的设备不能因为 VPN 已授权，就推断这项热点共享能工作。

## 分开看三种场景

| 场景 | 应确认的对象 |
| --- | --- |
| 手机本机 VPN 模式 | 本机应用是否进入 Android VpnService 路径 |
| root 系统模式 | 本机流量是否按该模式安装的系统路由处理 |
| 热点或局域网客户端共享 | 转发流量是否另有共享规则与辅助进程 |

2.3.10 固定标签的 `RootProxyManager` 包含本机系统流量处理，以及仅共享客户端流量的入口。后者可以在手机使用 VPN 模式时运行，但仍明确要求 root。不要把“可以配合 VPN 模式”误读成“无需 root”。

## 为什么手机成功不能代替电脑成功

预发布版源码对客户端共享使用独立的转发处理，把客户端流量引向核心 SOCKS 入站；它不只是复制手机本机的 VPN 授权。热点是否开启、客户端是否接入、路由规则是否安装、辅助程序是否启动，都需要分别核对。

这些源码路径说明设计边界，并不保证每款手机固件的热点实现都兼容。失败时保留 root 授权结果、共享启动错误及客户端网络信息，不用手机成功截图替代客户端结果。

## 按两台设备做验收

1. 先让手机本机在既有模式下工作，记录节点、网络和请求目标。
2. 在当前版本设置中核对共享选项及其权限提示，只使用自己的热点和测试设备。
3. 打开热点，确认测试电脑已获得地址、默认网关和基础网络连接。
4. 按客户端版本启用共享，查看日志是否有权限拒绝、辅助程序缺失或路由建立失败。
5. 手机与电脑分别建立新请求，分别记录结果。不要只复制一张手机延迟图。
6. 停止共享后，再确认手机和热点客户端基础网络恢复。

若电脑连热点本身就无法取得地址，应先处理热点基础连接。若已联网但共享启动失败，优先核对权限和服务日志，不直接重装订阅。

## 停止后的检查也属于完成条件

2.3.10 的实现会在启动前清理旧规则，停止时移除相关规则；安装失败也有回退处理。但这不等于你的手机已成功执行清理。故障后需要观察停止日志和实际网络结果，保留异常现场。

不要照抄陌生的全局防火墙清空命令来恢复热点。先停止应用对应共享功能，按已确认的版本和错误路径排查；只要权限、路由或日志仍不确定，就不能宣称共享完成。
